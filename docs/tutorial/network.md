# 连接 Wi-Fi 并检查网络

本章在设备触屏上建立 Wi-Fi 连接，再按需检查地址、路由和目标服务。适用于能够进入桌面的设备；管理员诊断命令在板端执行。

## 准备网络信息

准备接入点名称（SSID）和密码，确认管理电脑与设备之间允许通信。若后续需要使用云端服务，网络还应允许访问对应服务地址。

已通过网络远程管理设备时，关闭 Wi-Fi 或切换网络会中断当前会话。需要这样操作时，先保留触屏或已授权调试入口。

## 从触屏连接接入点

1. 在首页打开**无线网络**，确认 Wi-Fi 开关已开启。
2. 执行扫描，等待网络列表更新。
3. 选择目标 SSID，在连接窗口输入密码。
4. 提交一次连接请求，观察状态变化。
5. 等待网络显示已连接，再核对设备获得的 IP。

页面可能依次出现“正在发送连接请求”“请求已发送，等待连接”。这些提示表明连接仍在进行，不能直接进入更新或云端配置。已连接网络会更新连接标记；连续点击同一网络不用于重新提交密码。

| 当前结果 | 处理方法 |
| --- | --- |
| 扫描列表为空 | 确认接入点已开启，刷新扫描并检查距离；持续无结果时查服务日志 |
| “扫描未确认，请重试” | 重新发起一次扫描，观察是否结束；重复失败再做管理员诊断 |
| 连接失败或持续等待 | 核对 SSID、密码和接入点状态，记录完整提示后重试 |
| “Wi-Fi 已切换，但尚未确认保存开关偏好” | 检查当前实际连接，重试保存；不要把开关变化视为偏好已持久化 |

## 确认地址和路由

在**板端 shell**执行：

```sh
ip addr
ip route
cat /etc/resolv.conf
date
```

依次检查：

1. 正在使用的网络接口存在有效地址；不要使用 `127.0.0.1` 作为管理电脑访问地址。
2. 需要访问网段外服务时，有正确的默认路由。
3. 需要域名访问时，DNS 配置存在且符合当前网络。
4. 系统日期与时间合理，避免 HTTPS 校验因时间错误失败。

接口名由固件决定，不预先假定为 `wlan0`。将实际地址记录为后续 IPKVM 使用的“板端 IP”。

## 检查管理电脑能否访问设备

1. 在管理浏览器打开 `http://<板端IP>/`；已经配置 TLS 时使用对应 HTTPS 域名。
2. 确认出现 IPKVM 登录或首次密码设置页面。
3. 页面无法打开时，在板端执行：

```sh
aitvbox-ipkvmctl status
aitvbox-ipkvmctl log
```

服务正常而浏览器不可达时，检查电脑与设备的网段、防火墙、接入点客户端隔离及地址是否变化。IPKVM 页面可访问仅证明该局域网服务可达；云端服务和 WebRTC 媒体需各自验证。

## 检查保存与重新连接

1. 返回首页后重新打开无线网络，确认当前连接仍显示正确。
2. 需要验证持久化时，在计划维护窗口进行正常重启。
3. 启动后检查是否恢复原网络连接，重新记录 IP。
4. IP 变化时更新管理浏览器地址，不使用旧地址反复判断掉线。

保存网络的历史布局为 `/overlay/wifi/wpa_supplicant`，其中可能包含密码。排障时检查挂载、权限和错误日志，避免公开配置正文。

## 处理运行中掉线

在仍可访问的板端 shell 或串口执行：

```sh
cat /proc/sys/kernel/random/boot_id
cat /proc/uptime
logread | tail -n 80
dmesg | tail -n 120
```

记录掉线时间、触屏是否响应、启动 ID 是否改变，以及是否出现 SDIO/MMC 超时。日志先保存在受控目录，分享前遮盖网络名称、MAC、账号和设备标识。

完成本章的判据是：连接状态明确、地址有效、所需服务可达；重连和长期稳定性按实际执行结果另行记录。网络就绪后可继续[IPKVM](ipkvm.md)或[语音助手](ai-iot.md)。
