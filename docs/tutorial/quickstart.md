# 完成首次启动

适用前提：设备已安装与你的 PCB 配套的系统，能够正常供电启动。本文不需要在板端重新编译任何程序。

## 第一步：等到桌面完成交接

开机先出现启动画面，随后平台后端和桌面启动。正常结果是桌面出现、时间持续变化、触摸有响应。不要把停在启动图或刚显示一帧画面当作启动完成。

如果长时间停留在启动画面，先保留串口输出，再查 `/tmp/lv_backend.log` 与 `/tmp/lvglsim.log`。旧系统入口会等待后端 socket，新更新基线还涉及独立桌面启动器，详见[系统架构](architecture.md)。

## 第二步：记录版本

打开设置中的设备/更新相关页面，记下应用版本、系统版本、板型和产品版本（公共或私有）。如果界面没有完整信息，请管理员通过受控调试入口读取相应清单。

建议保存一张本地记录表：

| 项目 | 你的值 |
| --- | --- |
| 实物 PCB 修订 | 按板上标识填写 |
| 系统版本 / 应用版本 | 分开填写 |
| 产品版本 | public / private / 尚未确认 |
| 板端 IP | 联网后填写 |
| 固件来源和包哈希 | 引用交付清单 |
| 本次启动与触摸结果 | 实际通过或失败 |

## 第三步：配置网络和时间

从首页进入无线网络，扫描、选择网络并输入密码。等待显示已连接后，检查板端获得 IP，再确认路由和所需服务可达。Wi-Fi 已关联、获得地址、能访问互联网是三个检查点。

时间不正确会影响桌面显示、主题时段和 HTTPS 校验。按系统提供的时间设置/同步功能纠正后，再排查云端或证书报错。

## 第四步：检查基本交互

1. 在首页应用区左右滑动，确认页面指示随实际页数变化。
2. 打开设置，调整一次音量或亮度，返回桌面。
3. 重新进入设置，检查保存值；若提示保存失败，应保留错误并重试。
4. 打开“用户应用”，确认能返回首页；无已安装应用时显示空状态是正常情况。
5. 使用小屏版本时检查滚动区域，确认底部操作和返回入口可达。

新版开发 UI 与旧出厂固件可能不同。先对照[版本状态](version-status.md)，不要仅凭页面外观判断升级已安装。

## 第五步：按需求启用功能

- 手机播放音乐：进入[蓝牙音箱](network.md)，分别确认配对、连接与实际出声。
- 看电脑 HDMI：连接两条信号线，短时打开 [IPKVM](ipkvm.md)。
- 涂鸦或设备配对：先确认[产品版本和授权条件](ai-iot.md)。
- 安装扩展应用：管理员添加发布者公钥，再上传[签名 APP](user-app.md)。

不使用 HDMI 时关闭采集；结束远程操作后退出浏览器会话，避免长期占用输入或视频资源。

## 这一章的完成条件

桌面持续响应、触摸导航正确、版本有记录、网络地址明确、设置能保存，且能正常进入/退出至少一个应用。这里的日常检查不替代完整的升级、断电或稳定性验收。

失败时按[故障排查](troubleshooting.md)收集症状与时间。记录“发生了什么”和“看到什么”，避免用反复重启掩盖问题。
