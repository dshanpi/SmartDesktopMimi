# 制定检查清单并记录验收结果

本章面向开发与维护人员，将一次改动或交付拆为可执行检查，并把结果绑定到真实源码、产物和目标。

## 先固定本次验收对象

执行前记录：完整源码提交、产物 SHA-256、系统与应用版本、板型/修订、测试方法与时间。测试过程中替换产物时，建立新记录并重跑受影响项目。

| 验证层次 | 典型方法 | 结论适用范围 |
| --- | --- | --- |
| 来源与静态检查 | 文件、接口、许可、来源锁校验 | 指定输入和约束 |
| 主机验证 | 构建、协议、拒绝用例、渲染 | 指定主机环境与测试场景 |
| 实机功能 | 真实显示、触摸、声音、HDMI、USB | 指定设备和实际安装包 |
| 生命周期 | 升级、回退、断电、数据保留 | 指定版本配对与故障阶段 |

## 根据改动确定回归范围

- 文案或文档：构建、链接、布局、命令及事实一致性。
- 页面交互：输入事件、等待/成功/失败状态、返回与不同尺寸。
- 接口或 Provider：前后端兼容、能力查询、参数和错误处理。
- 更新器：信任、完整目标、事务、并发、健康和恢复。
- 驱动或系统：目标硬件功能、启动、运行依赖与系统回归。

定义每项输入、操作、预期结果和失败后的处理。避免只写“功能正常”。

## 执行设备基本功能检查

| 检查项 | 操作 | 通过判据 |
| --- | --- | --- |
| 启动与桌面 | 冷启动后进入应用并返回 | 显示、真实触摸、导航与持续响应正确 |
| 设置 | 改值、保存、重新进入 | 硬件反馈及保存值一致 |
| Wi-Fi | 连接、访问目标服务、重新连接 | 地址和服务可用，状态一致 |
| 蓝牙 | 配对、播放、暂停、断开重连 | 实际出声及状态正确 |
| IPKVM | 视频、普通键鼠、结束会话 | 画面更新、输入正确、资源释放 |
| 用户 APP | 安装、打开、返回、读取数据 | 版本与内容正确，数据按约定保留 |
| 云端能力 | 按授权条件完成业务 | 返回结果与实际设备/账号状态一致 |

HDMI 仅在相应项目期间开启，结束后关闭。账号、设备或云项目缺失时记录未执行及原因。

## 执行更新与拒绝检查

产品发布至少覆盖以下范围：

1. 正常升级，以及声明兼容范围的边界版本。
2. 错产品、同架构错板、错误修订、缺身份、ABI/库/接口不符时拒绝。
3. 错签名、损坏包、重放、路径逃逸、空间不足和下载中断。
4. 解包、切换、健康检查等阶段失败与恢复。
5. 配置、媒体、用户 APP、网络及工厂身份保留。
6. 应用与系统双向升级/回退配对，更新并发互锁。
7. 声明要求的断电恢复和持续运行项目。

断电、刷写和设备激活属于专门验收操作，应在对应计划与目标条件具备时执行。主机夹具结果与真实断电分别记录。

## 写出可复核的结果

| 状态 | 使用方式 |
| --- | --- |
| `passed` | 已执行，具体判据满足，附证据 |
| `failed` | 已执行，写明实际偏差与影响 |
| `not_run` | 尚未执行，说明原因 |
| `blocked` | 缺必要条件或被准入检查拒绝 |
| `deferred` | 已明确后置，仍列入剩余工作 |

记录模板：

```text
检查项：
输入/版本/产物摘要：
目标设备或主机：
操作与检查方法：
预期结果：
实际结果与状态：
证据位置：
失败原因或未执行原因：
后续处理：
```

将修复和复测追加到原失败记录之后，保留前后关联。旧包的通过结果不能直接转移给新包。

## 完成工程追溯检查

按项目规则记录稳定需求号、范围、流程、不变量、文件列表和真实证据，更新 `CURRENT_PROGRESS.md` 与索引。提交后在**产品源码根目录**使用本批真实起点：

```sh
python3 scripts/check_change_gates.py --base REVIEWED_BASE_COMMIT --head HEAD
```

替换实际 base 提交，检查退出码和覆盖结果。自动覆盖只检查记录与文件关联，语义、秘密隔离与功能仍需相应检查。

本教程的文档验证单独记录在 [DOCS077](../change-gates/REQ-MIMI-DOCS-077.md)，不计入产品实机验收。
