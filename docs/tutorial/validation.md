# 验证方法与完成标准

每一条验证结论属于某个输入、某个方法和某个目标。修改二进制以后，原包的通过记录不能自动转移到新包。

## 四层验证

| 层次 | 典型内容 | 能证明什么 |
| --- | --- | --- |
| 静态/来源 | 路径、接口、许可证、来源锁 | 输入符合约束 |
| 主机 | 构建、协议、拒绝用例、渲染 | 对应主机环境与场景行为 |
| 设备 | 冷启动、真实触摸、声音、信号和枚举 | 该硬件与该包的实际表现 |
| 生命周期 | 升级、回退、断电、数据保留 | 指定更新路径与恢复能力 |

文档站的路由与浏览器验证属于文档质量，不能计入后三项产品验收。

## 修改范围决定回归范围

改文案通常检查构建、布局和链接；改页面交互需要状态/输入及受影响分辨率；改接口需要前后端兼容；改更新机制需要事务恢复和目标拒绝；改内核/驱动需要对应硬件与系统回归。

不要为了增加数字而重复没有变化的测试；也不要因为主机测试很多就略过真实触摸。

## 产品版本必需检查

1. 正常升级与兼容边界。
2. 错产品、同架构错板、错误硬件修订、缺身份、ABI/库/接口不符时拒绝。
3. 错签名、损坏包、重放、路径逃逸、空间不足、下载中断。
4. 切换与健康检查各阶段故障、断电和恢复。
5. Wi-Fi/蓝牙、配置、媒体、用户 APP 和工厂身份保留。
6. 应用/系统双向配对与并发更新互锁。
7. 冷启动、顶栏、导航、返回、真实显示触摸和宣称支持的硬件功能。

HDMI 项短时开启并在结束后关闭。没有实物资源、账号或云项目时写 `blocked` / `not_run`，不能用夹具补成物理通过。

## 一份可接续记录

```json
{
  "scope": "示例：文档或指定应用功能",
  "source_commit": "填写实际完整提交",
  "artifact_sha256": "有产物时填写真实摘要",
  "target": "填写实际主机或设备身份",
  "checks": [
    {"name": "具体检查项", "status": "not_run", "evidence": "待执行"}
  ],
  "next_steps": ["尚待完成的工作"]
}
```

这是阅读模板，不是项目机器 schema。正式记录按 `docs/change-gates/` 和发布工具的真实格式创建，不能把占位值上传当作验收。

## 工程追溯

每批改动建立稳定需求号，记录范围、业务流程、失败分支、不变量、文件列表和真实证据。完成后更新索引与 `CURRENT_PROGRESS.md`。提交之后使用实际本批起点检查覆盖：

```sh
python3 scripts/check_change_gates.py --base REVIEWED_BASE_COMMIT --head HEAD
```

不能拿空差异或无关提交当比较基准。自动覆盖只能验证记录与路径，不证明秘密隔离、产品功能或证据真实性。

本教程站点的专属记录为[DOCS077](../change-gates/REQ-MIMI-DOCS-077.md)，与原产品验收分开。
