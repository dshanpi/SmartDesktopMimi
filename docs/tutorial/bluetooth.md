# 连接手机并播放蓝牙音频

小咪作为蓝牙音频接收端（A2DP Sink）播放手机声音。本章依次完成控制器就绪、手机配对、媒体输出和重连检查。

## 准备播放测试

准备支持蓝牙音频输出的手机和一段已知可播放的音频。先在手机本机播放一次，确认音源有声，再将手机与小咪音量设为适中。

配对、连接和实际播放是独立状态。手机显示“已配对”后，还需要选择媒体输出并检查声音。

## 开启设备蓝牙音频

1. 在小咪打开蓝牙音频页面，开启蓝牙服务。
2. 等待初始化结束，查看页面显示的设备名称和连接状态。
3. 在手机系统设置中开启蓝牙，搜索附近设备。
4. 选择与小咪页面对应的名称，完成手机提示的配对流程。

**检查结果：** 手机显示已连接，小咪页面同步显示实际连接状态。附近有多台设备时，应核对名称和设备标识后选择。

## 选择媒体输出并确认出声

1. 在手机的媒体输出选择中选中小咪。
2. 播放准备好的音频，确认声音来自小咪扬声器。
3. 分别调整手机和小咪音量，检查静音状态。
4. 在页面提供相应功能时，测试播放/暂停。

曲目标题、封面或播放状态由手机提供的 AVRCP 信息决定。音频可正常播放但部分曲目信息为空时，先检查播放器与手机支持情况。

## 断开后重新连接

1. 在手机停止播放，断开当前蓝牙连接。
2. 观察小咪回到实际断开状态。
3. 在手机已配对列表选择小咪重新连接。
4. 再次选择媒体输出并播放同一音频。

需要验证重启后的配对保留时，另记录重启前后设备标识、已配对状态和实际播放结果。

## 按症状处理失败

| 症状 | 优先检查 | 处理后重新验证 |
| --- | --- | --- |
| 手机搜不到设备 | 蓝牙开关、控制器初始化、页面状态 | 刷新手机扫描并重新配对 |
| 已配对但无法连接 | 对端是否仍连接另一台音频设备、设备服务是否就绪 | 重新连接并核对两端状态 |
| 已连接但无声 | 手机媒体输出、音源、两端音量及静音 | 用同一音源检查实际出声 |
| 曲目信息缺失 | 手机播放器与 AVRCP 信息提供情况 | 先确认音频功能，再检查信息显示 |
| 断开后一直等待 | 后端状态更新或初始化异常 | 保存日志后处理，不重复启动控制器程序 |

管理员在**板端 shell**执行：

```sh
hciconfig -a
ps | grep -E 'hciattach|lv_backend'
grep -E 'bt init deferred|deferred init waiting|hci0 is UP|service initialized' /tmp/lv_backend.log
logread | tail -n 100
```

控制器正常就绪时，`hci0` 应为 `UP` 或 `UP RUNNING`。`bt init deferred` 表示后端等待底层控制器，继续查看后续是否出现初始化完成，而不是在多个终端重复启动 `hciattach`。

## 核对持久化配置

历史 Tina 布局使用 `/overlay/bluetooth` 和 `/overlay/lib/bluetooth` 保存控制器配置与配对信息。恢复配对问题前，先核对该固件的实际挂载关系。不要以清空所有蓝牙目录作为首个排错步骤。

完成检查应记录：目标手机、连接状态、实际出声、播放控制、断开与重连。控制器 `UP` 单独不足以证明音频链路已完成。
